Scope, provenance and governance

Methodology and governance

The lab tests small proposals against an immutable USWDS release. It does not fork USWDS, claim official endorsement, or treat a passing automated run as an accessibility decision.

Stable baseline

{{sourceLock}}

The baseline is the pinned npm distribution plus authored fixture markup and a small fixture stylesheet. It is not a byte-for-byte copy of every official example. A newer USWDS release is reported by npm run sources:latest but never promoted automatically; promotion requires a reviewed decision.

What is compared

Baseline panes load the exact released CSS and JavaScript. Experimental panes load the same assets plus a separate MIT-licensed stylesheet and, where needed, extra markup. The comparison viewer does not mirror keyboard or mouse input between panes; independent pages are provided for real keyboard and assistive-technology testing.

Experiment categories

  • Component improvement: a change to an existing USWDS component.
  • New component: a proposal with no stable equivalent; the missing baseline is stated, not fabricated.
  • Cross-component capability: a systematic change such as appearance preferences.
  • Alternative implementation: a different approach to an existing interaction or layout problem.

Experiment lifecycle

Proposed → under investigation → prototype → automated evidence collected → ready for human review → changes requested / reviewed and accepted → submitted upstream → adopted upstream, or deferred / archived. Human review is recorded as one row in docs/EXPERIMENT-DECISIONS.md. AI may draft material but cannot mark its own work as human-approved.

AI assistance and human responsibility

AI assistance is disclosed per experiment. Generated code, tests, summaries, and review drafts are proposals. A human must inspect implementation quality, semantics, keyboard behavior, evidence, compatibility, maintenance impact, and upstream context. A successful build or a clean scanner run is not approval. See the AI disclosure and governance.

What is out of scope

This is not an official USWDS release channel, a competing government design system, a WCAG certification, or a complete replacement for upstream documentation. OGDS Elements and USWDS Elements are research links only; no runtime adapter is claimed until one is implemented and license-reviewed.

Contributing

Read the experiment contributor guide. Use npm run experiment:new to create a draft with no fabricated evidence, then implement a fixture and a deterministic test before requesting review.
