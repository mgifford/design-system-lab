Landing-page comparison

One service page, USWDS vs the OGDS hybrid

Same content, same viewport, same interactions. The left pane is pinned USWDS 3.14.0. The right pane uses USWDS 3.14.0 plus OGDS Elements beta.2 for the components OGDS covers.

This is a hybrid, not a full OGDS replacement. OGDS is used for the banner, header/primary navigation, and accordion. The alert remains USWDS because OGDS beta.2 does not export a built alert module. Hero, cards, search, footer, and every other component remain USWDS. What is not being claimed

This is not a complete OGDS page, not a prediction of every OGDS state, and not a WCAG conformance statement. The right pane is a hybrid. Components with no OGDS equivalent remain USWDS and are listed as unchanged.

OGDS components use shadow DOM. The Guidepup transcript covers the slotted light-DOM text, not the shadow-tree roles or internal states; browser tests, axe observations, and screenshots are the primary evidence for this page.

How the hybrid is composed

The left and right pages share content and state. The right page adds the OGDS token CSS and bundled web components, then replaces only the covered components. The remaining USWDS markup is unchanged so a difference is attributable to the OGDS layers, not unrelated content edits.

When OGDS names, versions, or component APIs change, update the pinned adapter and the component matrix; the left USWDS pane and the comparison shell stay the same.
